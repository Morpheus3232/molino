## 3. EXPERIENCIA DE USUARIO

### Flujo completo del usuario

```
VISITANTE
  → Ve Home (entra en 5 segundos: "Personal Intelligence Platform")
  → Click "Crear mi perfil" o "Explorar conocimiento"

SI CREA PERFIL:
  → Onboarding (nombre + fecha)
  → Profile (6 secciones: identidad, patrones, conexiones, timing, decisiones, evolución)
  → Explore (biblioteca de conocimiento)
  → Compatibility (conectar con entidades)
  → Share (compartir perfil)

SI EXPLORA:
  → Explore (biblioteca)
  → Knowledge pages (numerología, astrología, zodiaco chino)
  → Biblioteca (fuentes)
  → Method (transparencia)
```

### Dónde se rompe el flujo

1. **Home → Onboarding:** Funciona bien
2. **Onboarding → Profile:** Funciona bien
3. **Profile → Explore:** Funciona bien
4. **Profile → Compatibility:** Botón hardcodeado a Argentina
5. **Explore → Compatibility:** Botón hardcodeado a Argentina
6. **Knowledge → Profile:** `window.location.href` funciona pero es frágil
7. **Evolution:** Feature incompleta, confunde al usuario
8. **No hay "reason to return":** Sin daily energy, sin notifications, sin historial

### Primeros 5 minutos del usuario

1. **0-5s:** Home → "Personal Intelligence Platform" → tarjeta demo
2. **5-10s:** Click "Crear mi perfil" → formulario limpio
3. **10-20s:** Completa formulario → loading
4. **20-30s:** Llega al Profile → ve su nombre en grande
5. **1-2min:** Explora secciones → radar chart → patrones
6. **2-3min:** Ve shareable card → "Esto es para compartir"
7. **3-4min:** Explore → numerología, astrología, zodiaco chino
8. **4-5min:** Vuelve al profile → compatibilidad

### Lo que sobra o dispersa

1. **Evolution page** — Stub incompleto
2. **Analytics page** — Herramienta de desarrollo
3. **9 redirects** — Podrían ser middleware
4. **Portal page** — Redundante con Explore

## LO QUE NO DEBEMOS HACER

1. **NO copiar features de CUE** — Daily Energy de CUE es un widget; el nuestro debe ser una herramienta de reflexión
2. **NO crear un chatbot genérico** — La IA debe ser intérprete de datos, no conversador
3. **NO agregar autenticación compleja** — localStorage funciona para MVP; auth real solo si hay necesidad de relaciones
4. **NO crear una app móvil** — Web-first es nuestra ventaja; PWA puede ser suficiente
5. **NO agregar más dependencias** — El stack actual es suficiente
6. **NO crear dashboards SaaS** — Molino no es un producto de productividad
7. **NO agregar gamificación excesiva** — El valor está en el autoconocimiento, no en puntos
8. **NO agregar predicciones** — Esto destruiría la credibilidad
9. **NO agregar registro obligatorio** — La apertura es nuestra ventaja competitiva
10. **NO perseguir a CUE** — Nuestro camino es diferente: abierto, educativo, exploratorio
