## P0 — BLOQUEADORES (deben resolverse antes de cualquier otro trabajo)

### 1. Compatibility page usa usuario FALSO
- **Página:** `/compatibility/[entity]`
- **Problema:** Usa `calculateUserProfile('Usuario', '1995-12-25')` hardcoded. Todos los resultados de compatibilidad son para un usuario ficticio, no para el usuario real.
- **Impacto:** CRÍTICO — rompe la promesa de "Personal Intelligence". El usuario ve resultados que no le corresponden.
- **Solución:** Convertir a client-side con `useProfile()` o crear una API route que use los datos reales.

### 2. Entity detail page sin CTAs
- **Página:** `/entities/[id]`
- **Problema:** No hay botones de acción. El usuario llega a una página muerta sin forma de interactuar.
- **Impacto:** ALTO — el usuario no puede hacer nada con la información mostrada.
- **Solución:** Agregar "Ver compatibilidad" y "Volver a explore" buttons.

## P1 — PROBLEMAS IMPORTANTES DE PRODUCTO

### 3. "Ver compatibilidad" siempre va a Argentina
- **Página:** `/profile`, `/explore`
- **Problema:** El botón "Ver compatibilidad" siempre lleva a `/compatibility/argentina` sin importar el perfil del usuario.
- **Impacto:** ALTO — confuso y no personalizado.
- **Solución:** Llevar a `/explore` o a un selector de entidades.

### 4. Knowledge pages sin personalización
- **Páginas:** `/numerologia`, `/astrologia`, `/zodiaco-chino`
- **Problema:** Son páginas de referencia genéricas. No muestran los datos del usuario (su signo, su número, etc.).
- **Impacto:** MEDIO — no aprovechan que el usuario ya tiene un perfil.
- **Solución:** Agregar "Tu Life Path es X" o "Tu signo es Y" al inicio de cada página.

### 5. "Volver a mi perfil" usa `window.history.back()`
- **Páginas:** `/numerologia`, `/astrologia`, `/zodiaco-chino`
- **Problema:** Si el usuario llega directamente a la página (via URL), `history.back()` no funciona.
- **Impacto:** MEDIO — UX frágil.
- **Solución:** Usar `router.push("/profile")`.

### 6. Evolution page es un stub
- **Página:** `/evolution`
- **Problema:** El botón "Agregar milestone" crea entradas genéricas no editables. Hay un card "Próximamente" con features futuras.
- **Impacto:** MEDIO — parece incompleto.
- **Solución:** Ocultar de navegación principal hasta que esté completo, o mejorar el flujo.

### 7. Analytics page sin acceso
- **Página:** `/analytics`
- **Problema:** Cualquier usuario puede ver y borrar datos de analytics. No hay control de acceso.
- **Impacto:** MEDIO — datos sensibles expuestos.
- **Solución:** Ocultar de navegación, agregar auth básica, o eliminar si es solo para desarrollo.

## P2 — MEJORAS DE UX

### 8. Anchor roto `/profile#moment`
- **Página:** `/explore`
- **Problema:** El link "Ciclos" apunta a `/profile#moment` que no existe como `id`.
- **Impacto:** BAJO — link roto.
- **Solución:** Cambiar a `/profile` o agregar el `id` correcto.

### 9. Chinese character typo "能量"
- **Página:** `/` (home)
- **Problema:** En la sección de capas, texto dice "El momento actual y能量" (caracter chino accidental).
- **Impacto:** BAJO — error tipográfico.
- **Solución:** Corregir a "El momento actual y energía."

### 10. GitHub link apunta a github.com
- **Página:** `/biblioteca`
- **Problema:** "Contribuir en GitHub" lleva a `github.com` (homepage), no al repo de Molino.
- **Impacto:** BAJO — placeholder.
- **Solución:** Link al repo real o eliminar el link.

### 11. Header/footer ausente en compatibility
- **Página:** `/compatibility/[entity]`
- **Problema:** La página no renderiza `UniversityHeader` ni `UniversityFooter`.
- **Impacto:** MEDIO — inconsistencia visual.
- **Solución:** Agregar header y footer.

### 12. Score function shadowing en match page
- **Página:** `/match/[entityId]`
- **Problema:** Importa `getScoreColor`/`getScoreLabel` pero los redefine localmente.
- **Impacto:** BAJO — code quality.
- **Solución:** Eliminar las definiciones locales y usar las importadas.

## P3 — MEJORAS ESTÉTICAS

### 13. Knowledge pages son tarjetas de referencia delgadas
- **Páginas:** `/numerologia`, `/astrologia`, `/zodiaco-chino`
- **Problema:** Contenido muy brief (una oración por tema). Sin visuales, diagramas, ni elementos interactivos.
- **Impacto:** BAJO — no es crítico pero afecta la percepción de profundidad.
- **Solución:** Agregar más contenido, visuales, o conexiones con el perfil del usuario.

### 14. Evolution page muestra "Próximamente"
- **Página:** `/evolution`
- **Problema:** Card explícito dice que features futuras están por venir.
- **Impacto:** BAJO — transparencia, pero parece incompleto.
- **Solución:** Ocultar o eliminar la sección "Próximamente".

### 15. Analytics page usa emojis casuales
- **Página:** `/analytics`
- **Problema:** 📊, 👁️, 👤, 🤖, 🎯 en lugar de iconos SVG consistentes.
- **Impacto:** BAJO — inconsistencia visual.
- **Solución:** Reemplazar con iconos Lucide o SVG.

## A. QUÉ ESTÁ REALMENTE EXCELENTE EN MOLINO

1. **Home page** — La mejor página del producto. Comunica claramente qué es Molino, qué obtiene el usuario, y por qué debería crear su perfil. La tarjeta demo es efectiva.
2. **Profile page** — El corazón del producto. Jerarquía narrativa de 6 secciones, radar chart, shareable card. Se siente como un producto real.
3. **Onboarding** — Limpio, funcional, genera datos reales. La experiencia de "sesión efímera" genera confianza.
4. **Method page** — Excelente transparencia. Este tipo de página construye credibilidad.
5. **Biblioteca** — Curada y funcional. El search y filter funcionan bien.
6. **Diseño visual** — Consistencia premium en todas las páginas. Estética editorial, no SaaS genérica.
7. **Accessibility** — Focus states, aria labels, reduced motion, keyboard navigation.

---

## B. QUÉ LO DIFERENCIA DE UNA WEB GENÉRICA DE NUMEROLOGÍA/ASTROLOGÍA

1. **Multi-system approach** — No es solo numerología o astrología. Combina 3 sistemas + ciclos + patrones en un solo mapa.
2. **Personal Intelligence framing** — No se vende como "horóscopo" sino como "herramienta de autoconocimiento".
3. **Profile como producto central** — El profile no es una página de resultados, es una experiencia de exploración.
4. **Shareable card** — Mecanismo viral orgánico.
5. **Transparencia** — Method page explica limitaciones explícitamente.
6. **Sin registro obligatorio** — El usuario puede explorar conocimiento sin crear perfil.
7. **Código abierto** — Posicionamiento de confianza.

## C. CORE LOOP PRINCIPAL DEL PRODUCTO

```
1. Landing → "Qué es esto?"
2. Onboarding → "Creá tu mapa"
3. Profile → "Esto soy yo"
4. Explore → "Aprendé sobre los sistemas"

```


8. **Minuto 4-5:** Vuelve al profile. Explora compatibilidad.

## H. LA ÚNICA MEJORA QUE MÁS AUMENTARÍA LA PERCEPCIÓN DE VALOR

**Corregir la compatibility page para usar datos REALES del usuario.**

Razón: La compatibility es la feature más "wow" del producto. Cuando un usuario descubre que Molino puede analizar su compatibilidad con Argentina, Apple, The Beatles, o cualquier entidad, eso genera un momento de "esto es increíble". Pero actualmente la página muestra datos para un usuario ficticio, lo que destruye completamente esa experiencia. Corregir esto convertiría la compatibility de "demo" a "producto real" de un solo cambio.
